# 绘图与 SVG 重建的实际决策

## 参考图生成

内置图像模型生成或修改参考位图；SVG 由后续步骤实现。先明确图的科学关系，再约束排版：

```text
用途：科研机制图；主题与核心结论：[用户内容]
结构顺序及因果/结合关系：[来源支持的关系]
视觉：白底、平面矢量风格、统一细描边、受控色板、留白充足
标签：[准确文字]；重复对象同形同色
需保留：[参考图中的已认可结构]
此次只修改：[局部区域和目标]
不要将假说画成已证实的结合位点，不添加无来源箭头或结构。
```

有参考图时明确其角色是风格参考还是需要保留布局的修改目标。局部图片编辑使用当前图像工具；已经有 SVG 时直接编辑矢量源码。不要用整体重生成解决几个标签错位。

## 语义重建不是通用一键算法

Codex 根据每张图编写简短的绘图脚本/SVG，借助 `<path>`、`<ellipse>`、`<rect>`、`<line>`、`<polygon>` 和文字组重建。复杂度受图影响；必要时仅对复杂主体追踪，随后与干净的箭头/文字组合。不能把 PT 专用模板冒充通用转换器。

SVG 使用明确的 `viewBox`；最终投稿物理尺寸可在最后一步设置，例如 `width="180mm" height="105mm" viewBox="0 0 1800 1050"`。文字清单合并阶段采用同一像素画布，不在合并时同时换物理单位。

主轮廓使用尽量少的平滑控制点；箭头可用线段加独立三角形，减少导入 marker 差异。对虚线指定 dasharray、linecap，并在形状边界处终止。平面稿默认实心填充；确需透明或渐变时，应另外确认兼容路线，不直接通过本 skill 的严格平面检查。

SVG 中对象绘制顺序由文档顺序决定。按科学意义组织组并保留稳定 ID，避免全局替换相同颜色影响另一抗体/信号。移动局部标签时同时检查所属 Fab、表位、引导线和邻近标签。

## 文字清单

可由读图/OCR后核对得到；不要求某个 OCR 服务。`scripts/svg_pipeline.py merge-text --help` 是参数依据。以下是显式像素坐标示例（`y` 为首行基线）：

```json
{
  "canvas": {"width": 800, "height": 450, "coordinate_space": "pixel"},
  "text_elements": [
    {"id": "domain-a-label", "content": "Domain A", "x": 230, "y": 225,
     "font_family": "Arial", "font_size": 24, "font_weight": "400",
     "fill": "#18212B", "text_anchor": "middle", "rotation": 0, "paint_order": 1}
  ]
}
```

统一用 `pixel`，或显式 `normalized`；不要将归一化位置与像素字号混为一谈。多行基线/字号空间按脚本帮助执行。恢复 `²`、`⁺`、`−` 等真实字符；遇字体缺字时选择具有字形的字体，必要时明确用带大小/基线的 tspan，不能默默改数学含义。

通用合并助手将文字组放在几何上方，`paint_order` 仅排序文字。若标签需要穿插在几何层间，编辑分组顺序；不要声称此助手还原了原图的任意 z-order。不要对仍含原文字的位图直接追踪后叠加活文字，那会留下双层标签。

检查报告的 `text_contents` 是每个 `<text>` 内文本的原样串联，不自动在 tspan 之间添加换行；视觉换行由 tspan 的位置决定。原生导入核对会忽略空白差异，并保留字符内容不一致的失败门禁。

## 两层检查

机器检查：真实路径和活文字存在；无 `<image>`、base64 栅格、外部资源、脚本；没有平面工作流不支持的效果；输出与源文件不同。检查继承的 opacity 和内联 style，而非只看几何标签属性。

视觉检查：与参考图对照全局结构，再放大改变过的位置。边缘连续；没有浅色晕圈；有意留白/孔洞未被填黑；文字未变为轮廓；图例颜色和所属对象一致；箭头方向与端点正确；小元素彼此独立；标签无重叠。在最终物理尺寸下可读。

原始 PT 本例中，自动追踪曾产生 1095 条路径、782 种填充颜色和 174 个近白碎片。固定色板压到 371 条路径后仍产生黑块/轮廓断裂。最终由少量曲线和原语重建，得到 186 个几何对象、35 条 path、48 个文字对象；数值是历史参考，不是所有图的验收阈值。
